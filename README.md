# ChefJiw.ai

แอปสอนทำอาหารทีละขั้น พร้อมเชฟจิ๋วที่ตอบคำถามหน้าเตา สร้างด้วย Expo (React Native) และ Expo Router

## เริ่มใช้งาน

```bash
npm install
npx expo start
```

กด `i` เพื่อเปิด iOS simulator, `a` สำหรับ Android หรือสแกน QR ด้วย Expo Go

## คำสั่งตรวจ

```bash
npm run typecheck
npx expo lint
npm test
```

## โครงสร้าง

| ที่ | มีอะไร |
|---|---|
| `src/app/(tabs)/` | แถบล่าง 4 แท็บ: ร้าน สูตร ทำอาหาร ฉัน |
| `src/app/recipe/[id].tsx` | รายละเอียดสูตร เลือกตัวเลือก ปรับสูตร และวัตถุดิบ |
| `src/app/cook/[id].tsx` | โหมดทำอาหารเต็มจอ จับเวลา ถามเชฟ เหตุฉุกเฉิน และให้คะแนน |
| `src/data/recipes.ts` | ข้อมูลสูตรสองภาษา แผนทำอาหารวันอาทิตย์ (`SUNDAY_PLAN`) และการรวมรายการของที่ต้องซื้อ (`planShopping`) |
| `src/theme/tokens.ts` | สี ตัวอักษร ระยะ มุมโค้ง ของทั้งธีมสว่างและมืด หัวจอแต่ละแท็บใช้สีสดหนึ่งสี (`header`) การ์ดเด่นของจอใช้ชุด `vivid` (จอละใบเดียว) และ `onTint` เลือกสีตัวอักษรให้คอนทราสต์ผ่าน ตัว UI เรียบแบบแอป 인아웃: ฟอนต์ Anuphan ชุดเดียว การ์ดอื่นเป็นเทาอ่อนหรือสีอ่อนมากตามความหมาย (ธีมมืดเป็นสีเข้มอมสีเดียวกัน ตัวอักษรและปุ่มในการ์ดปรับตามธีมเองผ่าน `OnThemed` ใน `ui.tsx`) จานในตารางไม่มีกล่องครอบ แถบแท็บไม่มีสี ความน่ารักอยู่ที่ตัวละครกับฉาก ขนาดตัวอักษรมีสองชุด: `type` สำหรับหน้าทั่วไป (13 ถึง 36) และ `typeCook` ที่ใหญ่กว่าสำหรับหน้าทำอาหาร เลือกผ่าน `BigType` ใน `ui.tsx` ส่วน `wide` จำกัดเนื้อหาไว้ที่ 600 จุดแล้วจัดกลางบนแท็บเล็ต |
| `src/app/onboarding.tsx` `login.tsx` `paywall.tsx` `market.tsx` `plan.tsx` | แนะนำแอปครั้งแรก เข้าสู่ระบบ สมัครสมาชิก ราคาตลาด แผนวันอาทิตย์ |
| `src/lib/api.ts` | จุดเชื่อม backend จุดเดียว: ถาม AI คิดเมนู เช็กราคา เข้าสู่ระบบ ซื้อสมาชิก |
| `src/lib/` | การตั้งค่าที่บันทึกในเครื่อง ภาษาไทย/อังกฤษ สกุลเงินตามประเทศ โควตาคำถามฟรี |

## Backend (Supabase)

| ที่ | มีอะไร |
|---|---|
| `supabase/migrations/` | ตาราง `profiles` (สถานะสมาชิก) `ai_usage` (โควตารายวัน) `prices` (ราคารายวัน) และงาน cron อัปเดตราคา |
| `supabase/functions/ask` | ถามเชฟจิ๋ว: ฟรีวันละ 3 คำถาม (เบต้า 20) สมาชิกไม่จำกัด ล้มเหลวคืนสิทธิ์ มีบัญชีนับต่อผู้ใช้ ช่วงเบต้าไม่มีบัญชีก็ถามได้ นับต่อรหัสเครื่อง (`ai_usage_device`) และจำกัดรวมทุกเครื่องวันละ 300 คำถาม (`GUEST_TOTAL_PER_DAY`) deploy ด้วย `verify_jwt` = false เพราะผู้ใช้ทดลองไม่มี token ฟังก์ชันตรวจเอง |
| `supabase/functions/menus` | คิดเมนูจากของที่มี (นับรวมในโควตาเดียวกัน) |
| `supabase/functions/prices` | อ่านราคาล่าสุดของประเทศ |
| `supabase/functions/update-prices` | งานรายวัน ค้นราคาจากเว็บผ่านปลั๊กอิน web ของ OpenRouter แล้วบันทึก |

เรียกโมเดลผ่าน OpenRouter แยกตามงาน (ตั้งที่ `MODELS` ใน `supabase/functions/_shared/common.ts`): ถามเชฟใช้ GPT-6 Luna คิดเมนูใช้ Claude Haiku 5.5 อัปเดตราคาใช้ Claude Sonnet 5.5 แต่ละงานมีโมเดลสำรองให้ OpenRouter สลับเมื่อตัวหลักล่ม

โปรเจกต์จริง: `jqfjqsvpjzcktfrnvobo` (migration ทั้งหมด ฟังก์ชันทั้งสี่ และงาน cron รายวัน deploy แล้ว)

ที่เจ้าของโปรเจกต์ต้องตั้งเองใน Dashboard:

1. Edge Functions > Secrets: เพิ่ม `OPENROUTER_API_KEY` (ถ้าไม่มี ถามเชฟ คิดเมนู และอัปเดตราคา จะตอบ error)
2. Auth > Providers: เปิด Google และ Apple แล้วเพิ่ม `chefjiw://auth` ใน Auth > URL Configuration > Redirect URLs (LINE ต้องตั้งเป็น custom OIDC provider ภายหลัง)

ตั้งโปรเจกต์ใหม่จากศูนย์: รัน migration ตามลำดับ (ก่อนไฟล์ cron ให้เก็บ `project_url` ใน Vault ดูหัวไฟล์) deploy ฟังก์ชันทั้งสี่ (`update-prices` ปิด verify JWT เพราะตรวจ secret จาก Vault เอง) แล้วทำสองข้อบน

แอป: URL กับ publishable key ของ Supabase อยู่ใน `.env` แล้ว (ค่าทั้งสองเป็นค่าสาธารณะ) ถ้าจะชี้ไปโปรเจกต์อื่นให้ใส่ทับใน `.env.local`

เว็บสำหรับลองบนมือถือ: https://chefjiwai.vercel.app (โปรเจกต์ `chefjiw` บน Vercel deploy อัตโนมัติจาก `master`) build จาก `vercel.json` (`expo export -p web`) เปิดใน Safari แล้วกด แชร์ > เพิ่มไปยังหน้าจอโฮม จะเปิดเต็มจอ

ยังไม่ได้ทำ: ระบบซื้อในแอป (App Store / Google Play) ปุ่มสมัครสมาชิกจึงยังขึ้นว่ายังไม่ได้เชื่อมระบบ สถานะสมาชิกอ่านจาก `profiles.member` ซึ่งต้องให้ฝั่งเซิร์ฟเวอร์เป็นคนตั้งหลังตรวจใบเสร็จ

ทดสอบฝั่ง edge function: `cd supabase/functions && SUPABASE_URL=http://x SUPABASE_SERVICE_ROLE_KEY=x deno test --allow-env _shared/common.test.ts`

## หน้า waitlist (`waitlist/`)

หน้าเว็บหน้าเดียวไว้แชร์ในกลุ่มทำอาหารตาม `founder/launch.md`: ปุ่มลองแอปฟรี และลงชื่อรับชุด 12 จานโดยยังไม่ต้องจ่าย (จ่าย 99 บาทตอนชุดพร้อม เลิกรับสั่งจองตามผล `founder/panel-v4`) ข้อมูลเข้าตาราง `waitlist` (หน้าเว็บเขียนได้อย่างเดียว และบันทึกได้เมื่อติ๊กยินยอมแล้วเท่านั้น) เป็นไฟล์ HTML ไฟล์เดียวกับรูปในโฟลเดอร์ ไม่ต้อง build

ก่อนแชร์:
1. แก้ `CONFIG` ท้าย `waitlist/index.html`: `contact` (ช่องทางขอลบข้อมูล) ถ้ายังไม่กรอก หน้าจะขึ้นแถบเตือนด้านบน
2. อ่านเรื่องข้อมูลส่วนตัว (เก็บไม่เกิน 90 วันหลังเปิดตัว) ว่าตรงกับที่ตั้งใจ
3. เอาโฟลเดอร์ `waitlist/` ขึ้นโฮสต์ไฟล์นิ่งที่ไหนก็ได้ (Vercel, Netlify, Cloudflare Pages) แล้วแก้ `og:image` เป็น URL เต็ม รูปพรีวิวตอนแชร์ลิงก์คือ `waitlist/img/og.png`
4. ใช้ลิงก์แยกต่อกลุ่ม เช่น `?g=fb1` `?g=fb2` `?g=line1` จะได้รู้ว่าคนมาจากกลุ่มไหน

ดูผล (เป้า 100 คนลงชื่อใน 14 วัน) และชุดทดสอบในครัวจริงอยู่ที่ `founder/kitchen-test.md`:

```sql
select kind, source, count(*) from waitlist group by 1, 2 order by 1, 2;
select created_at, kind, name, contact, source from waitlist order by created_at desc;
```

มีคนขอลบข้อมูล: `delete from waitlist where contact = '...';`

## ตัวละคร

ทีมเชฟ 3 คน เป็นภาพแบน คนตัวเล็กอ้วนสัดส่วนราว 2.4 หัว วาดเรียบแบบรูปทรงสีพื้น: ไม่มีลายบนเสื้อผ้า ไม่มีถุงเท้า เชือกรองเท้า หรือกระเป๋า รองเท้าเป็นวงรีสีเดียว แก้มจาง ของประดับรอบตัวมีเท่าที่จำเป็น ต่างกันที่ขนาด สีผิว ทรงผม และสีชุด แต่ละคนดูแลงานของตัวเอง และใช้เฉพาะจังหวะที่มีความหมาย ไม่แปะทุกหน้า (ดู `MASCOT` ที่ `src/data/images.ts`)

| ตัวละคร | หน้าตาและชุด | ใช้ตอน |
|---|---|---|
| เชฟจิ๋ว | หมวกเชฟ ผมหน้าม้าปัดข้าง เสื้อแขนยาวฟ้า ผ้ากันเปื้อนเต็มตัวสีส้ม ถือกระทะ | ผัดกระทะที่หน้าร้านและหน้าแนะนำแอป ครบเวลา รอคำตอบ มีข้อผิดพลาด |
| ใบเตย | หมวกบักเก็ต ผมเปียคู่ เสื้อยืดเขียวมินต์ เอี๊ยมกระโปรงยีนส์ ถือถุงผ้าใส่ผัก | แผนวันอาทิตย์ รายการของที่ต้องซื้อ ราคาตลาด |
| น้องชิม | ฮู้ดหมีสีเหลืองสวมฮู้ด กระโปรงชมพู ถือช้อนใหญ่ | ชิมให้คะแนนตอนทำจบจาน หน้าตาเปลี่ยนตามคะแนน |

ท่าทางมีการเอนตัว เอียงคอ ก้าวขา กระโดด และนั่ง (พารามิเตอร์ `lean` `tilt` `feet` `lift` `drop` ของ `person` ในไฟล์วาด) ทุกท่าใช้หน้าเดียวกัน: ตาจุด ปากขีด

แท็บฉันมีปฏิทินทำอาหารของเดือนนี้ (วันที่ทำจบจานเป็นสติกเกอร์รูปจานนั้น) และเหรียญรางวัล 3 เหรียญ คิดจากจานที่ทำจบจริงในเครื่อง (`src/lib/calendar.ts`)

หัวจอ: ทุกหน้าเป็นสีเรียบสีเดียวกับตัวละครหนึ่งตัวชิดขวา (`lead` ของ `Screen`) ไม่มีฉากหลัง แนวเดียวกับแอป 인아웃 หน้าร้านเป็นข้อยกเว้น: ทั้งจอเป็นสีน้ำเงิน ไม่มีแผ่นขาว เชฟจิ๋วกับจานแนะนำอยู่กลางจอ ข้อความ ตัวเลขสรุป และปุ่มวางบนสีโดยตรง ภาพฉากเดิม (`scene-*.png`) ยังอยู่ใน `assets/images/chef` แต่แอปไม่ได้ใช้แล้ว เหลือ `kitchen.png` ของครัวจำลอง ทั้งแอปใช้ฟอนต์ Anuphan (หน้า waitlist ยังใช้ Mitr กับ IBM Plex)

การขยับ: `Float` ใน `src/components/ui.tsx` มี 4 แบบ คือลอยขึ้นลง โยกซ้ายขวา สั่นตกใจ และกระโดดพร้อมเงา ตัวละครทุกจุดในแอปใช้แบบใดแบบหนึ่ง และหยุดนิ่งเมื่อเครื่องตั้งค่าลดการเคลื่อนไหว ทุกท่าแยกเป็นหลายชั้น คือภาพตัว (`<ท่า>-body`) กับส่วนที่ขยับเอง เช่น `cook-wok` `shop-legL` `sip-spoon` แล้ว `Mascot` ซ้อนชั้นตาม `LAYERS` ให้ดูเป็นร่างเดียว: ทั้งตัวขยับไปด้วยกันก่อน (หายใจ โยกตัวตอนเดิน โยกช้าๆ ตอนคิด) หัวเป็นชั้นของตัวเอง (`<ท่า>-head`) เอียงหรือเด้งรอบคอ และตาเป็นอีกชั้น (`<ท่า>-eyes`) กะพริบเป็นระยะ แล้วแขนขาหมุนรอบข้อต่อของตัวเอง (หัวไหล่ สะโพก) ไม่เลื่อนทั้งท่อน ชั้นกำหนดในตาราง `SPLIT` ท้าย draw.py ซึ่งพิมพ์จุดหมุนของข้อต่อออกมาตอนรันด้วย แต่ละตัวมีจังหวะเร็วช้าของตัวเองและพักสั้นยาวไม่เท่ากันทุกรอบ จึงไม่ขยับพร้อมกันแบบเครื่องจักร `Actor` (เชฟในครัวจำลอง) ค่อยๆ เปลี่ยนท่าพร้อมย่อตัวนิดหนึ่ง กติกาเพื่อไม่ให้แอปดูเป็นเกม: จอหนึ่งมีตัวละครขยับได้ตัวเดียว คือตัวที่อยู่บนหัวจอ ตัวอื่นและตัวละครในการ์ดเป็นภาพนิ่ง (`<Mascot still />`) รูปจานไม่ลอย การขยับที่เหลือต้องมีความหมาย คือครบเวลา ได้คะแนนดี กำลังรอคำตอบ หรือเกิดข้อผิดพลาด

ผู้ช่วยเชฟ (`src/lib/assistant.ts`): ทุกขั้นมีปุ่ม "ทำแล้วไม่ได้" แตะปัญหาที่ใกล้เคียง แล้วเชฟตอบเป็น "ตอนนี้" (กู้จานนี้) กับ "ครั้งหน้า" (กันไม่ให้เกิดอีก) คำถามทุกข้อส่งรายละเอียดของขั้น (ทำอะไร ต้องเห็นอะไร ไฟ เวลา สูตรที่เลือก และคำตอบตอนชิมครั้งก่อน) ไปให้ AI ด้วย และหน้าถามแสดงว่าเชฟรู้อะไรอยู่ คำตอบตอนชิมเก็บไว้กับแต่ละครั้งที่ทำ ครั้งหน้าที่ทำจานเดิม เชฟเตือนตรงขั้นที่คำแนะนำนั้นใช้ หน้าสูตรสรุปให้ดู และบทพูดหน้าร้านอ้างถึง ข้อความที่ส่งให้โมเดลอยู่ที่ `supabase/functions/ask/prompt.ts` (ต้อง deploy ฟังก์ชัน `ask` ใหม่ ปุ่มจึงได้คำตอบสองส่วน)

ป้าย "กระทะใบเดียว" หรือ "หม้อใบเดียว" (`onePan` ใน `MENU`) ขึ้นที่การ์ดจานและหน้าสูตร ใส่เฉพาะจานที่ใช้ภาชนะใบเดียวจริง

ครัวจำลองในหน้าทำอาหาร (`src/components/kitchen-stage.tsx`): ครัวยาว (`kitchen.png`) มีตู้เย็น อ่างล้าง เขียง และเตา เชฟจิ๋วเดินไปจุดของขั้นนั้นโดยกล้องเลื่อนตาม แล้วทำท่าของจุดนั้น (คิดหน้าตู้เย็นที่เปิดอยู่พร้อมวัตถุดิบลอยขึ้นมา ล้าง หั่น คนกระทะ ดีใจตอนจัดจาน) ไฟเตาตามระดับไฟ ของในกระทะหรือหม้อเพิ่มทีละขั้นและกระดกตามจังหวะผัด มีไอร้อนลอย แต่ละขั้นมีของให้แตะเหมือนต้นแบบ: แตะหยิบวัตถุดิบในตู้เย็น (ลำดับไหนก็ได้) หมุนลูกบิดเตาจนถึงระดับไฟของขั้น แตะเขียงเพื่อหั่น เปิดก๊อก แตะถ้วยของเพื่อใส่ลงกระทะ แตะกระทะเพื่อกลับด้าน ตักขึ้น หรือคน และแตะข้างเตาเพื่อจัดจาน ของที่ต้องแตะตอนนี้มีวงสีเหลืองกะพริบ ป้ายมุมซ้ายบนบอกว่าต้องทำอะไร ครัวเปลี่ยนตามทีละแตะ แต่ละขั้นต้องแตะจุดในครัว (ตู้เย็น อ่าง เขียง เตา) ให้เชฟเดินไปก่อน ระหว่างเลือกกล้องถอยพอให้เห็นเชฟกับจุดที่ต้องไป (กลับมาทำต่อกลางจาน เชฟรออยู่ที่จุดของขั้นก่อนหน้า) พอเดินถึงกล้องซูมเข้า แตะผิดจุดมีป้ายบอกเฉยๆ ว่ายังไม่ใช่ตรงนั้น แตะคนในขั้นที่มีจับเวลาจะเริ่มจับเวลาของขั้นนั้นด้วย ครัวเป็นภาพช่วยให้เห็นขั้นตอน ไม่ใช่เกม: ไม่มีของหลอก ไม่นับแตะผิด ปุ่มไปขั้นต่อไปกดได้เสมอโดยไม่ต้องแตะ และคะแนนตอนจบมาจากคำตอบตอนชิมอย่างเดียว สิ่งที่ต้องแตะคิดจากสิ่งที่เปลี่ยนระหว่างขั้น (`actsAt` และ `shownStage`) ตารางว่าแต่ละขั้นยืนที่ไหนและมีอะไรในกระทะอยู่ที่ `src/data/kitchen.ts` (มีเทสต์ใน `kitchen.test.ts`) ท่าเดิน ผัด หั่น ล้างวาดใน draw.py เหมือนท่าอื่น

วาดเองเป็น SVG: แก้ท่า สี ชุด ฉาก หรือเพิ่มตัวละครที่ `assets/images/chef/src/draw.py` รันแล้วได้ SVG ใหม่ จากนั้น `node raster.js ..` ในโฟลเดอร์เดียวกันแปลงเป็น PNG

## สถานะ

ทำแล้ว: ทุกหน้าจอในต้นแบบที่อยู่ใน v1 พร้อมโหมดมืดและสองภาษา

**โหมดเบต้าเปิดอยู่** (`BETA` ใน `src/lib/beta.ts`) ตามข้อเสนอของบอร์ดใน `founder/board.md`: แอปเหลือแค่โหมดทำอาหารกับจานที่ทำเสร็จแล้ว ในประเทศไทย ซ่อนเช็กราคา ญี่ปุ่นกับอเมริกา คิดเมนูจากของที่มี ตัวกรอง จานที่ยังไม่เสร็จ และหน้าสมาชิก (ยังไม่มีระบบจ่ายเงิน) ถามเชฟฟรีวันละ 20 คำถามแทน 3 และพักงานอัปเดตราคารายวันบนเซิร์ฟเวอร์ไว้ โค้ดทั้งหมดยังอยู่

ปิดเบต้า:
1. `BETA = false` ใน `src/lib/beta.ts` (แอป)
2. `BETA = false` ใน `supabase/functions/_shared/common.ts` แล้ว deploy `ask` กับ `menus` ใหม่ (โควตากลับเป็น 3)
3. เปิดงานราคาคืน: `select cron.alter_job((select jobid from cron.job where jobname = 'update-prices-daily'), active := true);`

ยังไม่ทำ: ระบบซื้อในแอป และแอนิเมชันมาสคอต ราคาสมาชิกยังเป็นช่องว่าง

สูตรที่ทำตามได้: กะเพราหมูสับไข่ดาว ไข่เจียวหมูสับ แกงเขียวหวานไก่ (หม้อ 4 จาน เป็นจานฟรีสำหรับทดสอบกับคนจริงใน `founder/launch.md`) หมูพะโล้ไข่ และผัดพริกขิงหมูถั่วฝักยาว (อย่างละ 4 จาน) ทั้งห้าสูตรยังไม่ได้ลองทำจริง ต้องลองก่อนเปิดให้คนใช้

แผนทำอาหารวันอาทิตย์ (การ์ดในหน้าร้าน ไปที่ `/plan`): พะโล้ แกงเขียวหวาน และพริกขิง รวม 12 มื้อ มีลำดับการทำ รายการของที่ต้องซื้อรวมทั้ง 3 จาน ต้นทุนเฉลี่ยมื้อละ ฿40 เทียบข้าวจานละ ฿50 และวิธีเก็บ (กินจากตู้เย็นใน 3 วัน ที่เหลือแช่แข็งตั้งแต่วันอาทิตย์) ราคาเป็นราคาตัวอย่างในโค้ด

ทำหลายจานสลับกันได้ (ตามลำดับในแผน ทำแกงระหว่างพะโล้เคี่ยว): แต่ละจานจำขั้นที่ทำค้างไว้แยกกัน ตัวจับเวลาที่เริ่มไว้เดินต่อแม้ออกไปทำจานอื่น ขึ้นเป็นแถบบนหน้าทำอาหารของจานอื่นให้แตะสลับกลับ และในเครื่องจริงจะเด้งแจ้งเตือนเมื่อครบเวลาแม้เปิดแอปอยู่ ระดับไฟมี 4 ระดับ: ปิดไฟ ไฟอ่อน ไฟกลาง ไฟแรง

บันทึกผลการทำอาหาร: ทุกครั้งที่ทำจบจานและให้คะแนนชิม แอปส่งชื่อจาน คะแนน และรหัสสุ่มของเครื่องไปที่ตาราง `cook_runs` (เขียนได้อย่างเดียว ไม่มีข้อมูลส่วนตัว) ดูผลด้วย SQL เช่น `select recipe, count(*), avg(score) from cook_runs group by recipe;`
